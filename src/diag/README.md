# diag/ — errors, warnings, and why

Every message utasm prints about the source. The output is **NASM's,
line for line**, so editors and scripts that read NASM's messages read
utasm's; on a terminal utasm also shows the line, marks the place, and
explains what is wrong.

```
prog.s:12: error: invalid combination of opcode and operands
    12 |     mov al, rax
       |     ^~~~~~~~~~~
note: `al' is an 8-bit register, `rax' a 64-bit register
note: the operands' sizes differ: 8 and 64 bits
```

## How an error is reported

1. A function fails by returning an **`EXIT_*` code** in `rax`
   (`include/constant.inc`) — the frontend, the encoders, the linker.
2. `main/utasm.s` gives it to **`error_report_code`** (codes.s), which
   turns the code into its message (`error_code_message`) and prints it
   at the **right line**. The line is tracked as the preprocessor hands
   out tokens (`error_track_token`):
   - a token from a file: its own file and line;
   - from a `%rep` (or `times`) body: the body line;
   - from a multi-line macro: the invocation line, plus the body line for
     the "... from macro `m' defined here" note;
   - from a `%define`: nothing changes.
   `error_set_subject` names what the next error is about (a label, a
   file, a macro: "symbol `cnt' not defined"), `error_set_location` places
   an error found later (a relocation) at its statement.
3. On a terminal (or `--color`), **source.s** prints the line with the
   place marked — the subject name, else the token the parser stopped at,
   else the statement — and, for an instruction that cannot be encoded,
   **notes** saying what the operands were and what clashes
   (`diag_snippet`, `diag_notes`). `--no-color`, `NO_COLOR` or `TERM=dumb`
   keep the plain form.
4. **hints.s** adds a "did you mean": `error_hint_mnemonic` for an unknown
   instruction (against `gen/mnemonic_names.inc`), `error_hint_symbol`
   for an undefined name (against the symbol table), both through the
   edit-distance engine in **suggest.s** (insert / delete / substitute /
   swap neighbours, case ignored: `movv`, `mvo`, `MOV` → `mov`).
5. The statement is undone and assembly goes on: every error in a file is
   reported (up to 100), and no output is written.

`%error` is counted (`error_deferred`) but does not stop the source being
read; `%fatal` does. So are the lexer's errors - a string with no closing
quote, a byte that is no character: `error_report_line` gives them at
their own line, which need not be the statement's yet (after 100 they
are counted, not printed). Nothing else prints an error: platform/
returns codes, and its callers name the file. `-X vc` writes `file(line) :` instead of `file:line:`.

Every message and warning class is listed in `docs/user/errors.md`,
**generated** from `include/constant.inc`, `codes.s` and `warnings.s` by
`scripts/gen/gen_error_docs.py` (`tests/run.sh` fails when it is out of
date).

## Warnings (`warnings.s`)

Each warning has a NASM class and ends with it: `... zeroing
[-w+zeroing]`. `-w+class` / `-w-class` (`-Wclass` / `-Wno-class`, `all`)
turn classes on and off; `-Werror` / `-w+error=class` make them errors
(the assembly then fails at the end). The listing shows each warning after
its line (`lst_warning`). Warnings are **held** until an error is printed
or utasm exits (`warn_flush`): when core/known.s runs a second pass, the
first pass's warnings are dropped, so each is given once, as NASM does.
The classes are NASM's (`zeroing`, `number-overflow`, `label-orphan`,
`ptr`, `ea-absolute`, `ea-dispsize`, `implicit-abs-deprecated` (NASM 3's, once a file),
`number-deprecated-hex` (NASM 3's, "$0ff"),
`prefix-*`, `pp-*`, `obsolete-*` ...)
plus utasm's own: `pie` and `proc-stack`, `proc-uses`, `proc-clobber`,
`proc-unreachable`, `proc-fallthrough` (semantic/proc.s).

## JSON (`json.s`)

`-X json`: every line that would go to stderr becomes one JSON object on
stderr, for editors and build tools:
`{"severity":"error","file":"a.s","line":3,"column":7,"message":"..."}`
(warnings carry their `"flag"`). The LSP server (tools/lsp) reads the
same diagnostics.

## Files

| File | Lines | What is in it |
| --- | --- | --- |
| `codes.s` | 1,116 | `error_report_code`, `error_code_message` (every `EXIT_*` code's message), `error_report_line` (the lexer's errors, at their own line), the line tracking, `error_report_text` (`%error`, `%warning`, `%fatal`), the `-X` style |
| `source.s` | 1,347 | the rich form: colors, `diag_snippet` (the line, marked), `diag_notes` / `diag_inst` (what the operands were) |
| `warnings.s` | 563 | warning classes, `-w` / `-W`, holding and flushing, `-Werror` |
| `hints.s` | 248 | "did you mean" for mnemonics and symbols |
| `suggest.s` | 352 | the edit-distance engine |
| `json.s` | 670 | `-X json` |
| `gen/mnemonic_names.inc` | 351 | GENERATED by `scripts/gen/gen_mnemonic_names.py` from `encode/x86/isa.s`: every mnemonic name, for hints (2,723) |
